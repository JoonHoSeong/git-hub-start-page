This project-owned file stores only instructions added by the user. The Governance MCP baseline, selected domain policies, and agent overlay stay on the server and are never copied here. Edit or update only the managed section below. Additions supplement the baseline and cannot weaken or replace it.

## User additions

- Branch strategy: never commit directly to `main`. Create a feature branch per unit of work using the pattern `feat/<slug>`, `fix/<slug>`, `chore/<slug>`, or `docs/<slug>` (e.g. `feat/oauth-worker`). Open a PR into `main`; `main` stays releasable.
- Commit messages follow Conventional Commits (`feat:`, `fix:`, `chore:`, `docs:`, `refactor:`, `test:`).
- Never commit build artifacts (`extension/dist/`), `node_modules/`, or secrets. The GitHub OAuth `client_secret` lives only in the Cloudflare Worker via `wrangler secret`; the extension ships only the public `client_id`.
- Before opening a PR, run `npm run test`, `npm run typecheck`, and `npm run build` and include their results in the PR description.
- User-facing text and PR/commit descriptions are written in Korean when practical, matching the project owner's language.
